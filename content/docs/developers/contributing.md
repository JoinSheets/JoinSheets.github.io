- `main` is always clean and releasable — no dev-only artifacts. Day-to-day
  work happens on `develop`; larger changes and bug fixes get their own
  branch off `develop`.
- Versions are tagged on `main`; releases also publish a GitHub Release with
  the same archive attached as an asset.
- Propose a change via an issue, implement it in a branch, and open a pull
  request against `develop`.
